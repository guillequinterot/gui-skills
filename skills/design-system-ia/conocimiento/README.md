# conocimiento/

Aquí vive el **conocimiento aprobado y verificado** que no cabe en una referencia: hallazgos con fecha y fuente, listas de comprobación afinadas con casos reales y tablas de apoyo. Las nueve referencias de `references/` son el conocimiento base; esta carpeta crece con los casos.

## Qué guardar

- Hallazgos **verificados** (con cómo se comprobó y cuándo), por ejemplo un comportamiento real de Figma o de un verificador.
- Listas o tablas de apoyo que se repiten entre casos.
- Correcciones a lo que dicen las referencias (con la fecha; la referencia se actualiza cuando el mantenedor lo aprueba).

## Qué NO guardar

- Datos de clientes, marcas o personas (los casos van solo con código `caso-ds-NN`).
- Observaciones de un solo caso presentadas como regla: van a `memoria/inbox-aprendizajes.md` hasta que se repitan en dos casos o el mantenedor las apruebe.
- Cualquier cosa copiada de una fuente de terceros: se reexpresa y se atribuye (`CREDITOS.md`).
