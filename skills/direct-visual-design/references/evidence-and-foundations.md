## 1. Jerarquía de evidencia

Priorizar, en orden:

1. estándares oficiales y legislación aplicable;
2. investigación o texto original;
3. instituciones reconocidas;
4. autores especializados y documentación técnica;
5. casos de estudio verificables;
6. recursos prácticos y blogs.

Etiquetar una afirmación por su naturaleza. No usar números de conversión, porcentajes neurobiológicos o causalidad de negocio sin una fuente directa y un contexto comparable. Una correlación o un caso A/B no constituye una regla universal.

## 2. Design Thinking proporcional

Usar Design Thinking como marco adaptable, no como ceremonia obligatoria.

| Situación | Profundidad |
|---|---|
| Pieza táctica con brief completo | Confirmar necesidad, idear 1-3 rutas, prototipar y validar rápidamente |
| Campaña o identidad | Investigar audiencia/categoría, definir problema, divergir, converger, prototipar y probar |
| Producto digital complejo | Combinar investigación, arquitectura, flujos, prototipos y pruebas iterativas |
| Encargo ambiguo o de alto riesgo | No saltar a estética; aclarar problema, restricciones y criterio de éxito |

Usar el Doble Diamante para separar descubrir/definir y desarrollar/entregar. Permitir retrocesos e iteración; no asumir un proceso lineal.

## 3. Leyes de UX

Aplicar solo a interacción y con el contexto indicado:

| Principio | Uso correcto | Precaución |
|---|---|---|
| Hick-Hyman | Reducir o estructurar opciones cuando elegir es la tarea | Más opciones no siempre empeoran; experiencia, búsqueda y categorización modifican el efecto |
| Fitts | Dimensionar y ubicar objetivos según distancia, tamaño y dispositivo | No justificar botones enormes ni ocultar acciones secundarias peligrosamente |
| Miller/chunking | Agrupar información con significado | Evitar usar “7±2” como límite universal de elementos UI |
| Jakob | Aprovechar modelos mentales y convenciones conocidas | Innovar cuando la nueva solución aporta valor y se puede aprender |
| Tesler | Decidir dónde gestionar complejidad inevitable | Simplificar para el usuario sin ocultar información o control necesarios |
| Doherty | Dar feedback oportuno y mantener continuidad | No tratar 400 ms como requisito universal; medir tareas, red y expectativas |
| Von Restorff | Destacar lo excepcional para facilitar detección | Demasiados acentos destruyen la excepcionalidad |
| Peak-end | Cuidar momentos críticos y cierre | No ignorar la calidad del recorrido completo |
| Serial position | Reforzar inicio y final de secuencias | No usar para justificar ordenaciones que contradigan prioridad o lógica |

Complementar con investigación de usuarios y pruebas. Las leyes predicen tendencias bajo ciertas condiciones; no garantizan conversión.

## 4. Principios Gestalt

Usar como lentes perceptivas, no como mandatos:

| Principio | Pregunta de diseño |
|---|---|
| Proximidad | ¿La distancia comunica correctamente qué elementos pertenecen juntos? |
| Similitud | ¿Los elementos equivalentes comparten señales y los distintos se distinguen? |
| Región común | ¿Un contenedor aclara relaciones o añade ruido innecesario? |
| Conectividad | ¿La unión explícita comunica una relación real? |
| Cierre | ¿La forma incompleta se comprende sin ambigüedad dañina? |
| Continuidad | ¿La mirada puede seguir relaciones, alineaciones o secuencias? |
| Destino común | ¿El movimiento conjunto expresa agrupación o causalidad? |
| Figura-fondo | ¿Se distingue qué es principal, secundario e interactivo? |
| Simetría/orden | ¿La estabilidad ayuda al objetivo o conviene tensión asimétrica? |
| Prägnanz | ¿La organización más simple conserva el significado necesario? |
| Experiencia pasada | ¿La convención elegida coincide con audiencia, cultura y medio? |
| Punto focal | ¿La prioridad se detecta sin eliminar jerarquías secundarias necesarias? |

No exigir un único punto focal en toda composición. Diseñar una jerarquía de atención apropiada a la tarea.

## 5. Patrones de escaneo

Tratar F, Z, Gutenberg, layer-cake, spotted y otros patrones como descripciones posibles, no mapas inevitables. El comportamiento depende de contenido, idioma, intención, densidad, dispositivo y señales visuales.

- Usar F o layer-cake como hipótesis en páginas densas de texto.
- Usar Z como esquema compositivo posible en piezas simples, no como garantía ocular.
- Validar rutas críticas con pruebas o eye tracking cuando la decisión tenga alto impacto.
- En idiomas RTL o escrituras no latinas, reevaluar dirección y convenciones.

## 6. Semiótica visual

Analizar:

- **denotación:** qué muestra literalmente;
- **connotación:** qué asociaciones activa;
- **icono:** semejanza con el referente;
- **índice:** relación física o causal;
- **símbolo:** significado aprendido culturalmente;
- **código de categoría:** convenciones del sector;
- **riesgo cultural:** lectura distinta por región, grupo o momento.

Evitar asociaciones rígidas como “azul siempre comunica confianza” o “serif siempre comunica lujo”. Justificar color, forma e imagen en el contexto real.
